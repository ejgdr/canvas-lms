# Discussion Thread Summarizer — Self-Hosted Endpoint Configuration

This document describes how to point the Discussion Thread Summarizer at an
institution-operated model endpoint. The service uses constructor dependency
injection, so no code path requires a third-party model (NFR-2).

---

## How provider selection works

`SummarizationService` accepts a `client:` keyword on `initialize`. At the
production enqueue point (`SummarizationService.enqueue_for`), `ModelClientFactory.build`
selects the concrete adapter:

| Condition | Adapter used |
|-----------|-------------|
| `SUMMARIZER_ENDPOINT_URL` is set | `SelfHostedModelClient` |
| `SUMMARIZER_ENDPOINT_URL` is absent / blank | `StubModelClient` (local dev / CI) |

The factory is the **sole provider-selection point** — setting the env var is the
only operator action needed to switch from the default stub to your self-hosted
endpoint. No feature flag, Setting record, or code change is required.

The `discussion_thread_summarizer_with_cedar` shadow flag routes traffic through
Canvas's Cedar proxy. It is independent of this self-hosted path; both flags can
coexist on the same account, but Cedar-routed accounts should leave
`SUMMARIZER_ENDPOINT_URL` unset unless you are routing Cedar traffic through your
own endpoint.

---

## Required environment variables

| Variable | Required | Description |
|----------|----------|-------------|
| `SUMMARIZER_ENDPOINT_URL` | **Yes** | Full URL of the institution endpoint, e.g. `https://llm.example.edu/v1/summarize`. Must be reachable from Canvas worker processes. |
| `SUMMARIZER_ENDPOINT_TOKEN` | No | Bearer token sent as `Authorization: Bearer <token>`. Omit if your endpoint uses network-level authentication (mTLS, VPN, etc.). |

Both variables must be set on the processes that run Delayed Job workers, not only
on web processes — summaries are generated by background workers.

---

## Network and firewall requirements

- Worker processes must be able to make outbound **TCP connections** to the host
  and port in `SUMMARIZER_ENDPOINT_URL`.
- If your endpoint is inside an institution-controlled network, ensure Canvas
  worker nodes (or their egress NAT gateway) are in the endpoint's allowlist.
- TLS: the endpoint URL may use `http://` or `https://`. Production deployments
  should use `https://`. Canvas workers do not validate TLS certificates beyond
  the system trust store; for private CA certificates, add them to the worker
  container's trust store.
- No inbound ports need to be opened on Canvas worker nodes.

## Example: local development stub (Docker Compose)

The example below starts a minimal HTTP stub that always returns a valid
summarizer response. Use it to verify the adapter selection and audit log locally.

```yaml
# docker-compose.override.yml — local dev only; do not commit credentials

services:
  llm-stub:
    image: wiremock/wiremock:latest
    ports:
      - "11434:8080"
    volumes:
      - ./dev/wiremock:/home/wiremock
    command: ["--verbose"]

  web:
    environment:
      SUMMARIZER_ENDPOINT_URL: "http://llm-stub:8080/summarize"

  jobs:
    environment:
      SUMMARIZER_ENDPOINT_URL: "http://llm-stub:8080/summarize"
```

WireMock stub mapping (`dev/wiremock/mappings/summarize.json`):

```json
{
  "request": { "method": "POST", "url": "/summarize" },
  "response": {
    "status": 200,
    "headers": { "Content-Type": "application/json" },
    "jsonBody": {
      "themes": ["Main theme A"],
      "viewpoints": ["Majority viewpoint", "Minority viewpoint"],
      "open_questions": ["What are the next steps?"],
      "scope_mode": "default"
    }
  }
}
```

## Example: Kubernetes deployment

```yaml
# k8s/summarizer-endpoint-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: canvas-llm-endpoint
  namespace: canvas
spec:
  replicas: 2
  selector:
    matchLabels:
      app: canvas-llm-endpoint
  template:
    metadata:
      labels:
        app: canvas-llm-endpoint
    spec:
      containers:
        - name: llm-endpoint
          image: your-registry/llm-summarizer:latest
          ports:
            - containerPort: 8000
          env:
            - name: MODEL_PATH
              value: /models/llama-3-8b
---
apiVersion: v1
kind: Service
metadata:
  name: canvas-llm-endpoint
  namespace: canvas
spec:
  selector:
    app: canvas-llm-endpoint
  ports:
    - port: 8000
      targetPort: 8000
```

Set the Canvas env var on your worker Deployment:

```yaml
env:
  - name: SUMMARIZER_ENDPOINT_URL
    value: "http://canvas-llm-endpoint.canvas.svc.cluster.local:8000/summarize"
  - name: SUMMARIZER_ENDPOINT_TOKEN
    valueFrom:
      secretKeyRef:
        name: canvas-llm-secret
        key: token
```

## Verifying traffic never leaves the institution's network

1. **Network policy**: in Kubernetes, apply a `NetworkPolicy` that allows outbound
   traffic from Canvas worker pods only to the LLM endpoint service's pod selector.
   This prevents workers from reaching arbitrary external addresses.

2. **DNS**: use an internal DNS name (e.g. `*.svc.cluster.local`) — this name is
   only resolvable inside the cluster, giving a hard guarantee that the URL cannot
   route to the public internet.

3. **Audit log**: every generation attempt emits a JSON log line with
   `"model_identifier": "self-hosted:<host><path>"`. Filter production logs for
   `"event": "discussion_thread_summarizer.generation_attempt"` and confirm the
   `model_identifier` matches your endpoint host — it never contains the raw URL or
   credentials.

   ```json
   {
     "event": "discussion_thread_summarizer.generation_attempt",
     "thread_id": 12345,
     "scope_mode": "default",
     "model_identifier": "self-hosted:canvas-llm-endpoint.canvas.svc.cluster.local/summarize",
     "request_byte_size": 1024,
     "latency_ms": 210,
     "success": true,
     "error_category": null
   }
   ```

## "Verify self-hosted mode" site-admin smoke test

Run in a **Rails console** connected to your Canvas instance after setting the
env vars and deploying.

### Step 1 — Confirm factory selects the self-hosted adapter

```ruby
client = DiscussionThreadSummarizer::ModelClientFactory.build
puts client.class          # => DiscussionThreadSummarizer::SelfHostedModelClient
puts client.model_identifier  # => "self-hosted:<your-host><your-path>"
```

If this returns `StubModelClient`, `SUMMARIZER_ENDPOINT_URL` is not visible to this
process — check that the variable is set on worker processes, not only web dynos.

### Step 2 — Enable the flag and enqueue a job

```ruby
course = Course.find(<your_test_course_id>)
course.enable_feature!(:discussion_thread_summarizer)

topic   = course.discussion_topics.active.first
teacher = course.teachers.first

DiscussionThreadSummarizer::SummarizationService.enqueue_for(
  discussion_topic: topic,
  viewer: teacher
)
```

### Step 3 — Drain the queue

```ruby
Delayed::Worker.new.work_off
```

### Step 4 — Check the audit log

```bash
grep '"generation_attempt"' /path/to/production.log | tail -1 | python3 -m json.tool
```

Confirm:
- `"model_identifier"` starts with `"self-hosted:"`
- `"success": true`
- `"error_category": null`

### Step 5 — Confirm the metric counter

Check your metrics backend (Datadog / Prometheus) for:

```
discussion_thread_summarizer.generation_attempt{account_id="<global_id>"}
```

This counter increments once per successful generation. A missing increment
with `"success": true` in the log indicates a metrics pipeline issue, not an
adapter issue.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `model_identifier: "DiscussionThreadSummarizer::StubModelClient"` | `SUMMARIZER_ENDPOINT_URL` not set on workers | Set var on Delayed Job process environment |
| `"error_category": "transport_error"` | Network or TLS failure | Check firewall rules; verify URL is reachable from worker node |
| `"error_category": "schema_invalid"` | Endpoint response does not match schema | Confirm endpoint returns `themes`, `viewpoints`, `open_questions`, `scope_mode` keys |
| `"success": false` + `"error_category": "unknown"` | Unexpected exception in adapter | Check worker logs for the full stack trace |
| `SUMMARIZER_ENDPOINT_URL is not configured` in logs | Variable visible to web but not worker | Redeploy workers with variable set |
